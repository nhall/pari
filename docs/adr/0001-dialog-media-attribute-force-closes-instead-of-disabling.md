# Dialog's `media` attribute force-closes instead of disabling

`pari-disclosure` already has a `media` attribute: outside the query it fully disables the JS enhancement and leaves the underlying markup visible, with no open/close side effects to unwind. `pari-dialog` reuses the same attribute name for consistency, but its behavior necessarily differs: when the query stops matching, an open dialog is force-closed through the normal `hide()` path (unlocking scroll, firing `dialog:close`), and the trigger and `deeplink` auto-open are both gated from opening it while non-matching. We considered mirroring disclosure's "disable but leave as-is" behavior, but a native `<dialog open>` sits in the top layer with focus trapped and scroll locked — there's no coherent "disabled but visible" state to fall back to, so closing is the only option that leaves the page in a valid state. When the query starts matching again, the dialog stays closed rather than auto-reopening, since a modal reopening itself and re-stealing focus on a resize event was judged worse than requiring an explicit re-trigger.
